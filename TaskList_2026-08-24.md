## Decisions taken while writing this

**1. The waiter read policies do not test `is_anon_session()`.** `015`'s write
policies do, so this is a deliberate departure. Being bound in
`waiters.auth_user_id` is already the stronger statement — `link_waiter_to_auth`
refuses an owner session — so the claim test could only ever be redundantly true,
and a redundant condition on a read path is just one more way for a future auth
change to break every waiter's roster silently. Reasoned in full at `019:96-112`.

**2. `cover_request()` is an RPC, not a column-level UPDATE grant.** The grant
was the cheaper option and it closes the smaller half of the hole: it controls
*which columns* a waiter writes, never *which values*, so `status = 'approved'`
stays reachable and a waiter can still approve their own swap. The RPC decides
both.

**3. `cover_request()` returns `NULL` for a lost race and raises for a broken
one.** Someone else covering the shift two seconds earlier is an ordinary
outcome, not a fault, and it gets its own toast. An unlinked device or an owner
session raises, so the client sees a code instead of silence.

**4. The dev switcher gets a replacement rather than being left broken.** It
reads the roster with no session — that is the point of it, it exists to get you
*out of* having no identity — so `019` blinds it completely. Leaving it dead
would mean burning an invite link for every waiter test from here on. `dev/021`
is a deliberate, narrow reintroduction of anonymous reads **on dev only**, where
the staff are seeded fakes, and it exposes five columns: no phone, no token, no
`auth_user_id`, no pattern. The switcher is physically absent from production —
`osmica.html:3938` returns on `IS_PROD_HOST` before a single line of it runs.
